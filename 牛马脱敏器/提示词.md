# 项目开发提示词：牛马脱敏器

请开发一款名为「牛马脱敏器」的 Windows 桌面小工具。

这是一款面向打工人的轻量级、幽默、自嘲型娱乐软件。通过牛马状态、每日抽签、工作日程和实时工资累加等功能，让用户在枯燥的工作中获得一点乐趣。

产品核心理念：让每一个打工人都能直观地看到自己今天为老板创造了多少价值，以及自己距离下班还有多远。

要求从零开始设计和开发，建立原创视觉体系，不使用现成产品的界面模板。

---

# 一、产品定位

产品名称：牛马脱敏器。

产品类型：Windows 桌面小工具。

产品特点：

- 轻量、简洁、幽默、有趣。
- 完全离线，不依赖网络。
- 无需注册、登录和服务器。
- 所有数据保存在本地。
- 启动后即可使用。
- 最终打包为独立 Windows EXE。

产品不是企业管理软件，不是效率管理平台，也不是复杂的数据分析仪表盘。

重点是提供有趣、直观、具有职场共鸣的体验。

# 二、视觉设计

建立一套完全原创的视觉设计体系。

## 2.1 整体风格

采用温暖、复古、简约、轻松、有质感的设计方向。

视觉关键词：

- 奶油色、米黄色、低饱和度暖色调。
- 柔和渐变和细腻的材质纹理。
- 适当的透明质感和柔和阴影。
- 圆润自然的界面元素。
- 精致的字体和清晰的信息层级。
- 适当留白，避免视觉拥挤。
- 融入幽默、荒诞、自嘲的职场文化元素。

整体应该具有独立设计感，不能像普通企业管理后台，也不能像套用模板生成的通用软件。

## 2.2 原创设计要求

所有视觉元素均需独立设计，包括：

- 软件品牌标识。
- 牛马主题插画。
- 功能图标。
- 界面布局。
- 配色体系。
- 字体与排版规范。
- 按钮和进度条。
- 动效与交互反馈。

不使用现成软件的界面布局，不复制其他产品的设计，不简单拼接通用 UI 组件。

## 2.3 牛马形象

设计专属的牛马主题插画，作为软件的品牌视觉核心。

形象风格要求：

- 有趣、幽默、具有辨识度。
- 带有打工人的疲惫和无奈。
- 可以通过不同表情表达情绪。
- 不要幼稚的儿童卡通风格。
- 不要夸张的 3D 游戏角色风格。
- 可以适当融入领带、咖啡、工牌、磨盘等职场元素。

牛马插画可以作为界面主体，也可以作为背景装饰，但不能影响信息阅读。

## 2.4 界面原则

- 不采用复杂侧边栏。
- 不堆砌大量卡片。
- 不使用复杂仪表盘。
- 不做传统企业管理系统布局。
- 不使用过度科技感的设计。
- 不要过度装饰。
- 突出关键数据和核心信息。
- 保持界面简洁、舒适、易读。

# 三、核心功能

软件包含四个核心功能。

## 3.1 牛马状态

展示用户当前的牛马成长状态。

主要内容：

- 牛马等级。
- 当前经验值。
- 距离下一级所需经验。
- 当前牛马称号。
- 今日工作状态。
- 累计工作天数。

可以根据工作时间、完成工作日等数据增加经验值。

设计一套有趣的等级体系，例如：

- 初入职场的小牛马。
- 熟练的打工牲口。
- 资深职场老牛。
- 公司的顶梁柱（自封）。
- 永不停歇的生产队驴。
- 传说中的职场永动机。

等级提升需要有明确的反馈，包括经验增加、称号变化和简单动画。

## 3.2 牛马每日抽签

提供每日随机抽签功能。

主要内容：

- 每日运势。
- 今日签文。
- 今日宜做事项。
- 今日忌做事项。
- 牛马指数。
- 今日摸鱼建议。

签文类型可以包括：

- 上上签。
- 上签。
- 中平签。
- 下签。
- 下下签。
- 特殊隐藏签。

签文内容需要幽默、有梗、有职场共鸣。

例如：

上上签：今天适合准时下班，老板不敢留你。

中平签：工作平稳，工资稳定，梦想暂缓。

下下签：今日宜闭嘴，忌主动承担工作。

特殊签：老板画饼，建议配茶食用。

功能要求：

- 每天默认可以抽签一次。
- 抽签结果保存在本地。
- 支持查看历史抽签记录。
- 抽签过程具有简单有趣的动画。
- 每日根据本地日期自动刷新抽签资格。
- 不需要联网获取运势。

## 3.3 牛马拉磨日程

帮助用户查看当天的工作时间和下班倒计时。

支持设置：

- 上班时间。
- 午休开始时间。
- 午休结束时间。
- 下班时间。
- 每周工作日。
- 是否计算午休时间。

主要展示：

- 当前工作状态。
- 今日工作进度。
- 今日已工作时长。
- 距离下班剩余时间。
- 今日工作时间进度条。

根据当前时间自动判断状态：

- 尚未上班。
- 工作中。
- 午休中。
- 已下班。

根据工作进度动态显示幽默文案。

例如：

「距离上班还有30分钟，抓紧享受自由。」

「已经工作2小时，牛蹄开始发热。」

「距离下班还有1小时，坚持住，胜利就在眼前。」

「今日任务完成，恭喜成功逃离磨盘。」

支持自定义工作时间，能够正确处理跨天工作时间和不同工作日设置。

## 3.4 牛马每秒工资累加

这是整个软件最核心、最有趣的功能。

用户可以设置：

- 月薪。
- 每月工作日数量。
- 每天工作时长。
- 工资发放日期。
- 午休是否计薪。

根据设置自动计算：

- 时薪。
- 分钟收入。
- 每秒收入。
- 今日累计劳动收入。
- 本月累计劳动收入。
- 今日满勤可获得收入。

在有效工作时间内实时累加工资，金额持续滚动更新。

功能要求：

1. 实时更新收入数字。
2. 精确计算每秒收入。
3. 工作时间之外停止累加。
4. 午休时间根据配置判断是否计薪。
5. 支持跨天和跨月。
6. 软件关闭后重新打开，能够根据本地时间重新计算。
7. 修改工资或工作时间后自动重新计算。
8. 金额计算避免浮点精度误差。
9. 本月累计收入与今日收入分别统计。
10. 正确处理节假日和非工作日的配置。

可以加入幽默提示：

「今天的你，又为老板的新车贡献了一个轮毂。」

「你的每一秒，都在变成老板的资产。」

「恭喜，你刚刚赚到了半杯奶茶钱。」

「工资到账之前，你的每一秒都很值钱。」

# 四、主界面设计

主界面是整个软件的核心，需要重点打磨。

优先展示：

1. 当前日期和时间。
2. 当前上班状态。
3. 距离下班倒计时。
4. 今日累计收入。
5. 当前每秒赚钱速度。
6. 今日工作进度。
7. 本月累计收入。

其他功能通过简洁的交互入口进入：

- 牛马状态。
- 每日抽签。
- 工作日程。
- 工资设置。

主界面不要把所有功能都堆在一起。

根据重要程度安排视觉层级，最重要的数据要足够醒目。

主界面应该让用户打开软件后，第一眼就能看到自己距离下班还有多久，以及今天已经赚了多少钱。

# 五、交互与体验

基本要求：

- 软件启动后直接进入主界面。
- 主要信息无需多次点击即可查看。
- 功能入口清晰。
- 操作简单直接。
- 支持窗口拖动。
- 支持窗口缩放。
- 支持最小化到系统托盘。
- 支持始终置顶。
- 支持关闭窗口后根据设置选择退出或隐藏到托盘。
- 支持开机启动设置。
- 支持修改工资和工作时间。
- 支持本地数据保存。

适当加入轻量动画：

- 收入数字滚动。
- 工作进度条变化。
- 牛马表情变化。
- 抽签动画。
- 等级提升动画。
- 下班状态切换动画。

动画需要轻量，不影响软件性能。

# 六、文案与个性

整体文案采用幽默、自嘲、轻松的职场风格。

不要过度正能量，不要说教，也不要做成严肃的效率管理工具。

文案需要有真实打工人的情绪共鸣。

示例：

- 「上班不是为了梦想，是为了下个月的房租。」
- 「你不是在工作，你是在用生命兑换工资。」
- 「再坚持一下，马上就能继续坚持。」
- 「今天的牛马表现不错，老板看了都想再安排点活。」
- 「下班倒计时开始，灵魂已经提前离职。」
- 「今天少摸一次鱼，明天老板多买一套房。」
- 「你的工资正在缓慢增长，老板的利润正在快速增长。」

文案可以根据不同工作状态动态变化。

文案内容可以通过本地配置管理，方便后续扩充。

# 七、设置功能

设置页面保持简单，只提供必要配置。

包括：

1. 工资设置。
2. 工作时间设置。
3. 每周工作日设置。
4. 午休计薪设置。
5. 每月工资发放日。
6. 窗口置顶设置。
7. 开机启动设置。
8. 系统托盘设置。
9. 数据备份与恢复。
10. 恢复默认设置。

首次启动时，引导用户设置月薪和工作时间。

不要求用户填写过多信息，完成基本设置即可开始使用。

# 八、数据与计算逻辑

所有数据保存在本地。

建议数据结构包括：

- 用户工资配置。
- 工作时间配置。
- 每日工作记录。
- 每日收入记录。
- 每日抽签记录。
- 牛马等级和经验。
- 软件界面配置。

数据持久化可以使用 JSON 或 SQLite。

计算要求：

- 使用 Decimal 或整数最小货币单位进行金额计算。
- 时间计算统一使用明确的本地时间规则。
- 正确处理跨天工作。
- 正确处理跨月统计。
- 正确处理非工作日。
- 关闭软件后不能丢失数据。
- 软件重新启动后能够根据时间重新计算收入。
- 修改配置后历史记录不能被错误覆盖。

需要明确区分：
- 实际已赚收入。
- 按标准工作日计算的预估收入。
- 本月累计收入。
- 今日预计满勤收入。

避免将预估收入和实际累计收入混淆。

# 九、技术选型

优先选择轻量、稳定、易于打包的 Windows 桌面开发技术。

可选技术：

方案一：
- Tauri。
- Vue 3 或 React。
- TypeScript。
- SQLite 或本地 JSON。

方案二：
- Python。
- PySide6。
- SQLite 或本地 JSON。

根据实际情况选择一种方案，不要同时引入多套技术栈。

技术要求：

- 完全离线运行。
- 不依赖远程 API。
- 不需要后端服务。
- 不需要云端数据库。
- 不需要用户账号体系。
- 不加载远程字体和图片。
- 不依赖网络验证。
- 优化启动速度。
- 控制内存占用。
- 支持 Windows 10 和 Windows 11。
- 最终能够打包成独立 EXE。

优先考虑软件体积、启动速度、稳定性和维护成本。

# 十、开发实施步骤

按照以下顺序开发：

第一阶段：产品结构与视觉设计

- 明确软件整体结构。
- 设计原创品牌视觉。
- 确定配色、字体、图标和组件规范。
- 完成主界面设计。
- 确保整体视觉统一。

第二阶段：核心功能实现

- 实现牛马状态和等级系统。
- 实现每日抽签。
- 实现工作日程和倒计时。
- 实现实时工资计算。
- 实现工资和工作时间配置。

第三阶段：数据持久化

- 实现本地数据保存。
- 实现历史记录。
- 实现配置修改和数据恢复。
- 实现重新启动后的数据恢复与重新计算。

第四阶段：交互优化

- 完善动画和交互反馈。
- 完善系统托盘。
- 实现窗口置顶。
- 实现开机启动。
- 优化软件启动和使用体验。

第五阶段：打包与测试

- 打包 Windows 独立 EXE。
- 检查运行依赖。
- 测试断网运行。
- 测试工资计算。
- 测试倒计时。
- 测试跨天和跨月。
- 测试本地数据持久化。
- 测试软件重新启动。
- 测试 Windows 10 和 Windows 11 环境。

# 十一、最终交付标准

最终交付以下内容：

1. 完整项目源代码。
2. 可运行的 Windows 桌面软件。
3. 原创 UI 设计资源。
4. 完整的四项核心功能。
5. 本地数据持久化。
6. Windows 独立 EXE。
7. 简单的使用说明。

必须实现真实功能，不允许仅提供静态 UI 原型。

不允许使用占位数据冒充真实功能。

不允许出现点击无响应的按钮。

不允许依赖网络才能运行。

必须实际启动软件并验证核心功能。

# 十二、最重要的开发原则

1. 优先保证四项核心功能完整。
2. 优先保证视觉品质和使用体验。
3. 保持产品轻量，不要过度设计。
4. 不要擅自增加复杂功能。
5. 不要把软件做成企业后台管理系统。
6. 不要为了技术复杂度引入不必要的架构。
7. 所有功能都必须能够在本地真实运行。
8. 视觉设计必须原创，具有独立品牌辨识度。

**最终目标：打造一款有审美、有幽默感、有实际趣味、轻量且完全离线的 Windows 牛马专属桌面小工具。**
